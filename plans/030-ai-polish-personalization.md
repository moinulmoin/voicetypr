## 1. Problem (re-diagnosed)
Three failures, in order of user harm:
1. **Discovery/setup wall.** Onboarding never mentions AI polish (`OnboardingDesktop.tsx:283-306` — no AI step). Enabling it is a self-discovered 6–7 step BYOK gauntlet (find screen → provider → external signup → key → model from up to 49 → toggle). Lock icon on AI modes (`EnhancementSettings.tsx:766`) reads as paywall next to the Upgrade-to-Pro onboarding screen. Most users never see polished output.
2. **Decision-layer spaghetti.** "Which enhancement runs" is encoded 3× (`EnhancementPreset` prompts.rs:109, mirror `WritingMode` writing.rs:31, TS union ai.ts:3), resolved in 4 functions, `ai_enabled`×preset clamped in 6 sites (prompts.rs:183, writing.rs:414/427, shortcuts.rs:287, lib.rs:1698, EnhancementsSection.tsx:129/454), Rust↔TS migration logic hand-mirrored, cache invalidation manual across 8 call sites. UI: 16 concepts, 2 sidebar screens, 4 names for one feature, Voice Commands referenced but uneditable, 8 formatting shortcuts shipped unbound.
3. **Quality levers unset.** No temperature (provider default ~1.0) / no max_tokens anywhere in `src-tauri/src/ai/`; `"stream": false`; blocking insert behind full LLM response (30s budget, ai.rs:1042); `sanitize_ai_output` (executor.rs:150) strips only control chars — model preambles get typed at the cursor; captured active-app context stops at preset selection and never reaches the prompt; instrumentation = one log line.

Competitive read: Wispr Flow wins on **restraint-first cleanup + ambient app-context injection + proper-noun auto-learning + <700ms p99**; its liabilities are privacy (screenshot scandal), reliability (75+ outages), $15/mo. Open position nobody holds: **Wispr-grade defaults + local-first trust + BYOK economics + cross-platform.** superwhisper/VoiceInk lose on defaults, not capability — "powerful but must configure" is punished; that is VoiceTypr today.

## 2. Goals
1. Two personas, one rule: **regular user = one switch + automatic behavior; advanced user = an Advanced layer that overrides it.** Architecture must make new features cheap on both sides.
2. Polish quality at Wispr grade on the same BYOK models: restraint contract ("edit like a copyeditor, never a ghostwriter"), hardened output contract, app-aware formatting.
3. One name, one screen, guided setup. Zero silent failure: user can always tell whether text was polished.
4. Latency measured, then attacked. Smooth dictation UX is the core service; polish must never make it feel worse.

## 3. Non-goals (this plan)
Learning loop / fix-last (Phase 5 roadmap — surface built here, feature parked). No local polish model, no bundled cloud (pending §9.3). No fine-tuning. No screen OCR. No new modes. No transcript content in telemetry.

## 4. Target architecture
- **Single source of truth:** `EnhancementPreset` is the one encoding; `PersonalDictation` = polish off; `ai_enabled` derived at read time; `WritingMode` deleted.
- **One resolver:** pure `resolve_pipeline_config(settings, active_app, key_state) -> EffectiveConfig`, called by recording, shortcuts, UI. Kills the 6-site clamp.
- **Module split:** `writing.rs` (~3.9k lines) → `writing/settings.rs`, `writing/library_rules.rs` (deterministic engine), `stt/vocabulary.rs` (4 engine compilers), `writing/pipeline.rs` (process_transcription). `ai/` stays as-is — it is the clean seam.
- **Rust↔TS contract:** golden-fixture parity test for preset migration / requires-ai / defaults / labels (prompts.rs:125-170 ↔ ai.ts:19-69).
- **Deterministic layer always on** regardless of polish state (it also feeds STT vocab — writing.rs:1302-1607); lives under Advanced.

## 10. Agent CLI as a polish provider — RESEARCHED 2026-07-02, verdict: SHIP AS OPT-IN BETA (own phase, after Phase 3)
Detect installed agent CLIs and offer them as a **no-API-key** polish provider via a third `AiRuntime` (`ai/cli_runtime.rs`). Two live-tested research passes on founder's machine. **Ship order (research-final 2026-07-02): Pi → Claude Code → Codex.**

Watch: npm rename in flight, single dominant author (company-backed since Apr 2026); pin versions.
- **Claude Code — GO, second (founder's quota theory CONFIRMED).** Trimmed call (`--system-prompt` + `--tools "" --strict-mcp-config --no-session-persistence --safe-mode`, empty cwd) measured **169 input tokens ($0.0015, 3.5s)** vs **~26.7k tokens ($0.0219, 5.8s)** with the default harness — a 158× reduction; polish becomes a rounding error on a Pro/Max plan. ToS still gray (exec-binary tolerated, token extraction banned — NEVER touch keychain); keep the kill-switch + disclaimer. `--bare` (fast path) remains API-key-only, no date for subscription support.
- **Codex CLI — GO, third, with metered-plan warning.** 3.3–4.9s; OpenAI explicitly permits plan reuse; `model_instructions_file` truly replaces base instructions BUT tool schemas + user's skills catalog + env context are non-removable → **~9.4k tokens/call floor** (best trim from 12.5k); warn users it drains ChatGPT plan quota at dictation frequency. `codex app-server` daemon (first-party) for warm mode.
- **Amp — dropped (founder call 2026-07-02;** docs-confirmed NO-GO anyway: `-x` consumes paid credits only, no system-prompt control, ~$0.025–0.03/call). **Replaced by oh-my-pi (OMP) — GO (researched 2026-07-02): same adapter as pi.** Fork of pi by can1357 (15.6k★, binary `omp`, ~3 releases/day): keeps `-p --mode json --system-prompt --no-tools -m provider/model` 1:1 and `--mode rpc` warm framing. - **OpenCode — NO-GO for spawn-per-call; revisit via `opencode serve` only if demanded.** Root-caused: `run` silently retries failing APIs forever without printing the error (open bug class #8203/#17516) + env-var footgun; `serve` + `POST /session/:id/message` (per-request model/system/tools) is the only sane integration.

So when the CLI provider is selected, keep a **persistent warm session** (claude `-p --input-format stream-json` long-lived process / `codex app-server` daemon — the same mechanism their own IDE integrations use), started at app launch / recording start alongside the existing connection warming, recycled every ~20 requests to stop context accumulation. Realistic warm per-call: **1.5–3s** ("a couple of seconds"). Direct API (300–900ms) remains the recommended default; CLI provider labeled "No API key needed — uses a coding CLI you already have. Slightly slower, shares your subscription limits."

- **Mandatory hardening:** hard 8–10s kill-timeout → raw-transcript fallback; empty temp cwd + isolation flags; pinned JSON output validated; version/feature detection at setup (flag drift is real — `--max-turns` already removed); auth preflight cached at setup time, never per-dictation.
